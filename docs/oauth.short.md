# Криптографічна специфікація OAuth2
[Детальніша версія](./oauth.md)

## 1. Access Token (PASETO v4.p)

* **Алгоритм:** Асиметричний підпис (`PASETO v4.p`, приватний/публічний ключі в `.env`).
* **Життєвий цикл (`exp`):** 5 хвилин.
* **Пейлоад:** Містить `userId` та `sessionId`.
* **Валідація:** Вимагає верифікації Refresh Token; ротація останнього відбувається не при кожному запиті, а за таймером.

## 2. Refresh Token та Безпека Сесій

* **Зберігання:** У таблиці `sessions` (hashed) та в кукісах користувача (сирий `base64url` без паддінгу).
* **Генерація БД-хешу (HMAC-SHA512):**
* **Ключ (`SESSION_HMAC_SECRET`):** 64 байти (128 символів у hex, зберігається в `.env`).
* **Пейлоад (Big-Endian):** `sessionId` (8 байт) + `userId` (16 байт) + `rawRefreshToken` (32 байти) = **56 байт**.
* **Формула:** `HMAC-SHA512(k_refresh, sessionId || userId || b64urlDecode(refreshToken))` -> результат 64 байти.


* **Захист від спуфінгу:** Порівняння через `crypto.timingSafeEqual`.
* **Захист від CSRF/XSS кукіс:** `HttpOnly`, `Secure`, `SameSite=Strict`.
* **Ротація:** Використання двох полів (`refresh_token` та `previous_refresh_token`). Старий токен дійсний у межах короткого вікна (наприклад, 3 хвилини).

## 3. State (Захист OAuth2 Callback від CSRF)

* **Генерація Нонсу:** 32 байти (43 символи `base64url` без падінгу).
* **Формат State:** Зв'язує провайдера з криптографічним підписом:
`state = provider || "_" || b64urlEncode(HMAC(k_state, provider || "_" || b64urlDecode(nonce)))`
* **Правила:**
* Назва провайдера **не повинна** містити символ `_` (валідується в коді).
* Кукіси нонса мають налаштування: `SameSite=Lax`, `HttpOnly`, `Secure`, обмежений `Max-Age`, та видаляються відразу після успішного callback.
